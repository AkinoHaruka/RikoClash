## 1. 目标与范围

在 `C:\TRAE\VPN\RikoClash`、分支 `codex/riko-clash` 上改造完整 CMFA Android 客户端，保留订阅、节点选择、规则、DNS、统计、应用分流和后台服务能力。

第一份可测试交付物是独立包名的 RikoClash APK，能够使用现有服务器主线路，并完成真实上传、下载测试。第二份交付物增加内置 WARP 手动备用；自动切换在手动路径、故障与恢复都验收后加入。

两条路线：

```text
主线路：应用流量 → Riko TUN / Mihomo → 现有服务器入口 → 目标站
备用线：应用流量 → Riko TUN / Mihomo → 内置 WARP → 同一服务器入口 → 目标站
```

gRPC / WS / XHTTP 用于客户端到服务器的代理传输。服务器域名是否经过现有 Cloudflare 入口，实施时核对；“主线路”只表示不强制加入 WARP，不能据此声称绕过所有 Cloudflare 设施。

- 用户仅安装 RikoClash；内置 WARP，不要求安装官方 WARP 或运行第二个系统 VPN。
- 主线路失败时不得擅自改成 `DIRECT` 访问目标，备用也不得变成 Cloudflare 公共出口直接访问目标。
- 首版沿用订阅中显式配置的分流规则，并在 UI 说明 DIRECT 规则、应用排除及局域网绕过范围；全局代理模式另行验收。
- 保留现有 WS / gRPC；所有 Riko 生成或导入的 XHTTP 节点固定为 `stream-one`，服务端反向代理必须支持该模式的双向 HTTP 请求。
- 保留 CMFA 的 Kotlin / XML / DataBinding 界面与 Go 核心。Rust 仅在现有 Go 无法覆盖且证据充分时评估，不为换语言重写核心。
- 不改动原 CMFA / Riko-VPN-APP，不启动或改动用户当前 Clash，不把云端作为首次测试环境。
- 原规划阶段不安装 APK、不切换 VPN、不修改服务器、不推送、不发布。2026-10-06 用户明确授权本 XHTTP `stream-one` 任务；任何云端变更仍须先通过 WSL Compose 测试。

- [ ] 核对 WARP 外层 Socket protect 的结果、绑定物理网络及取消。业务服务器 DNS、目标 DNS、注册/端点引导分开设置，避免启动循环。
- [ ] 先支持手动切换；WARP 失败时备用报错并阻断该线路，必须由用户切回主线，自动策略在 RC-07 加入。
- [ ] 能力按模式验证：源码 h3-l4proxy 不提供原生 UDP ListenPacket；gRPC 封装的应用 UDP与 XHTTP H3 的外层 QUIC 分别测试。首版只启用有证据的组合，未支持的组合在 UI 标明。

验证：编译层与 UDP 能力测试；Android 真机 WARP→服务器→目标请求；停止 WARP、损坏身份、阻断服务器的故障测试；结合核心拨号事件与必要抓包/服务端观测证明备用没有直接拨号服务器，日志必须脱敏。

完成条件：单个 VpnService，手动主备切换可用；备用确实进入 WARP并经服务器出口，断开 WARP 不绕行；上传下载完成，支持范围明确。

回退：功能开关禁用备用，回到已验证主线路；旁路候选仅在内置方案具体阻碍无法解决时另立设计，不自动叠加第二 VPN。

### RC-07：主备状态与自动切换

上下文：核心 fallback 组选中某节点不等同于完整产品状态，探测必须经过指定线路且不能误判服务器或目标故障。

工作范围：拟新增 service/route 策略状态机、service remote/model、app 与 design 的线路状态。

- [ ] 提供主线、WARP 备用、自动三种明确模式；首个备用版默认手动，自动作为显式设置。
- [ ] 状态包括停止、连接主线、主线可用、连接备用、备用可用、恢复探测、无可用线路；区分服务运行、探测就绪与本次连接失败。
- [ ] 探测经指定节点覆盖 DNS、握手与目标；采用多次失败、冷却、恢复连续成功及指数退避，阈值可测试且有记录。
- [ ] 本地离线暂停探测；服务器整体失败不得循环注册 WARP；单测速网站拒绝访问不得直接判断 WARP 故障。
- [ ] 切换时定义新连接选路和旧流清理，gRPC/XHTTP 连接池及 WARP 通道按需关闭；已建立会话不承诺无损迁移。
- [ ] 订阅更新、手动切换、网络变化、停止同时发生时保证状态与实际选路一致；显示原因与最近成功验证时间。

验证：状态机测试覆盖抖动、超时、两线都失败、取消、恢复；真机故障注入覆盖只坏主线、只坏 WARP、服务器坏、网络离线和订阅更新竞态。

完成条件：自动切换/恢复有真实新连接证据，无频繁切换、无 DIRECT 静默回退、状态不把 TUN 启动当连通。

回退：关闭自动模式，保留手动主备；不改系统其他 VPN。

### RC-08：Riko 界面与诊断体验

上下文：沿用完整 CMFA 功能，先做真实数据与可用操作，避免界面有开关但核心无对应能力。

工作范围：app 的 Main/Proxy/Profiles/Settings/Logs 页面、design 页面与布局资源、通知与快捷入口。

- [ ] 首页展示开关、节点、主备线路、上传/下载速率、累计流量、最近错误；数据来自 service/core。
- [ ] 订阅页面保留导入/更新/删除及错误，节点页保留分组、选择、排序与延迟；备用状态与节点延迟不混为同一指标。
- [ ] 设置页面标明规则/全局、DNS、IPv6、应用分流、局域网、WARP、自动策略的实际生效范围。
- [ ] Riko 品牌、深色与浅色、空态、加载、错误、大字体、无障碍和通知一致；不以整套 Compose 重写作为前置。
- [ ] 诊断包含构建、节点类型、脱敏入口、线路、测试目标、字节和耗时；导出过滤订阅 URL、UUID、私钥、身份、Token。

验证：真机逐页操作、空/错/慢状态、服务重启后的状态同步、通知与快捷操作；导出脱敏检查，失败操作有可见结果。

完成条件：所有可见操作有真实实现和结果，用户可知道当前线路及上传表现，原 CMFA 核心管理功能保留。

回退：恢复上一版资源/页面，保留配置数据格式兼容。

### RC-09：生命周期与性能回归

上下文：短请求成功不能证明日常稳定，WARP 还会引入长连接、网络栈和耗电变量。

工作范围：service 生命周期与网络观察、core 通道关闭、测试报告；按问题定位最小修改。

- [ ] Wi-Fi/移动网络切换、离线恢复、前后台、熄屏、进程终止、VPN 授权撤销、配置更新和连续启停。
- [ ] TCP/UDP、DNS、IPv6、大包、长上传与下载、HTTP/2/3 支持组合；失败不能卡死或留下旧 FD/连接池。
- [ ] 对照 RC-04 再跑三轮主线路和备用线路，记录内存、CPU、温度、电量条件和包版本；不要求备用达到主线路相同带宽。
- [ ] 至少一次 30 分钟持续传输和一次 2 小时后台稳定观察；记录异常而非只记录总时长。
- [ ] 单独报告 Android 始终开启 VPN/无 VPN 阻断的测试范围；应用进程死亡后的全局阻断不能仅靠应用状态机承诺。

完成条件：主线路通过性能回归门槛，备用可完成上传下载且故障可恢复；关键场景通过或明确限制，严重崩溃、丢配置、持续 0 上传阻止进入 RC-10。

回退：关闭有问题的组合或自动策略，保留最近已验证 APK 与数据兼容记录。

工作范围：签名配置、构建脚本、README、NOTICE、GPL/第三方材料、候选交付记录。

- [ ] 使用 RC-02 已确定的独立 Riko 发布身份与签名，缺失签名明确阻断候选发布；密钥不进入仓库或日志。
- [ ] 构建目标 arm64 与所需其他 ABI，测试 Release 优化后的 JNI、服务、反射、订阅和链路。
- [ ] 记录 APK 摘要、签名摘要、主/核心提交、工具链、资产锁和已知限制；提供对应修改源码及许可证材料。
- [ ] 用同包名、同 Release 签名的前后两个候选验证升级保留数据；新增存储字段有迁移测试，降级兼容范围明确。Debug 与 Release 分包验证，跨包数据迁移若未实现必须如实标为未支持，并保留 Debug 原数据。
